# Spatial node-pool node allocation verification (Block 60)

## Current status

Block 60 (`zone_spatial_grid_node_pool_alloc_node`, `func_001F2320`) is
registered as `NonMatching` in `configure.py`.

The pure C++ implementation in `src/zone_spatial_grid_node_pool_alloc_node.cpp`
matches all 376 instruction bytes (`0x178`) of the original PlayStation 2 PAL
executable (`orig/SLES-50282/AOK.ELF`) after resolving its single external call
relocation to `func_1F21E0`. However, the reference object generated by splat
contains 44 relocations (treating struct offsets within the node pool as symbol
references), whereas the compiled function contains exactly one relocation.
Because reference relocation records do not match, the unit remains `NonMatching`.

## Binary slice boundaries

The executable `PT_LOAD` mapping places file offset `0x1E0` at virtual address
`0x100000`, so `VA = file_offset + 0xFFE20`.

| Property | Value |
|---|---|
| Function | `func_001F2320` |
| Virtual address | `0x1F2320` |
| File offset start | `0xF2500` |
| Code size | 376 bytes (`0x178`) |
| Delay slot instruction | `0x1F2494` (file offset `0xF2674`) |
| Slice end | `0xF2680` (virtual address `0x1F24A0`) |
| Alignment padding | 8 bytes (`nop`) |

## Preserved behavior

`func_001F2320` allocates a 64-byte spatial node from the pool:

1. **Capacity expansion:** If available node count at offset `+0x138830` is
   zero, calls `func_1F21E0(self, self->capacity_138834)` to add a new zone.
2. **Recycled node reuse:** If the free list at `+0x138820` is non-null, pops
   the head node, updates the head pointer using the link pointer at offset
   `node + 12`, decrements available count, and returns the recycled node.
3. **Active zone carving:** Otherwise, retrieves the active zone from
   `table_138810[field_138824]`, computes node address as `base + elem_idx * 64`,
   decrements available count, and increments `field_138828`.
4. **Zone exhaustion:** If `field_138828` reaches the capacity stored in
   `table_138814[field_138824]`, advances `field_138824` to the next zone and
   resets `field_138828` to 0. If `field_138824` reaches `count_138818`, sets
   `field_138824 = -1`.

## Relocation analysis

The compiled function contains exactly one relocation:

| Offset | Type | Symbol | Address |
|---|---|---|---|
| `0x28` | `R_MIPS_26` | `func_1F21E0` | `0x1F21E0` |

After resolving this single relocation, the resolved instruction SHA-256 equals
the original binary slice:

```text
247fb1a37e99842abc26d8a869971c572c66c7d9c6ace9726834d1aa2f8bcb07
```

The splat reference target contains 44 relocations due to large structure
offset symbols (`D_00138810`, `D_00138814`, `D_00138818`, `D_00138820`,
`D_00138824`, `D_00138828`, `func_138830`, `D_00138834`). The strict
matching gate correctly blocks approval until the reference target matches.

## Verification tooling

- `scripts/verify_node_pool_alloc_node.py`: Resolves the single JAL relocation,
  verifies 376/376 byte equality against the pinned ELF, and validates relocation
  records.
- `scripts/verify_node_pool_alloc_node_cli.py`: Command-line interface returning
  exit code 1 when the strict matching gate fails.
- `tests/test_node_pool_alloc_node_provenance.py`: 10 test cases asserting
  literal byte equality, rejection of corrupted instructions, rejection of
  unverified symbols, and CLI exit codes.
- `tests/native/zone_spatial_grid_block60_test.cpp`: Native 32-bit test verifying

  `zone_spatial_grid_node_pool_alloc_node` is registered as `complete: false`.
